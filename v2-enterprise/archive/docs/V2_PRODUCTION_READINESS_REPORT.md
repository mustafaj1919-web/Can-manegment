## 2. تفاصيل تدابير الجاهزية لكل محور (Readiness Details)

### أ. جاهزية خادم الخلفية (Backend Readiness - 100%)
* **تصفير التحذيرات (0 Warnings)**: تم حل وإصلاح كافة تحذيرات المترجم CS8602 (Dereference of a possibly null reference) بنجاح كامل في ملف `AuthController.cs`.
* **مستوى معالجة البيانات**: معالجة معمارية الأوامر والاستعلامات (CQRS) بالكامل عبر MediatR بنمط نظيف وفصل كامل لطبقات النظام.
* **إدارة الاستثناءات والأخطاء**: تفعيل معترض أخطاء شامل (Exception Handling Middleware) يقوم بتسجيل الأخطاء وعرض استجابة موحدة للواجهة بدون كشف تفاصيل الأكواد الحساسة.
* **تسجيل الأحداث (Logging)**: إدماج Serilog لحفظ السجلات المهيكلة محلياً في ملفات دورية (`logs/`) وعرضها في بيئة التطوير.

### ب. جاهزية واجهة المستخدم (Frontend Readiness - 100%)
* **موقع المشروع المستقل**: يتواجد كود الواجهة الأمامية بالكامل داخل المجلد الفرعي `v2-enterprise/frontend` (حيث يتوفر ملف `package.json`).
* **تكامل الـ API**: ربط عميل Axios بالكامل بـ JWT Bearer Token المخزن في الـ `sessionStorage` والتحكم التلقائي بحالات الجلسات المنتهية 401.
* **البناء والانفصال الفني**: تمكين تجميع التطبيق بنمط `standalone` لتقليل حجم الحزمة التشغيلية وسرعة التخديم بـ Turbopack.
* **تبديل الفروع ذهنياً**: إمكانية تبديل الفرع النشط في الواجهة وتحديث الـ Token والبيانات محاسبياً وعملياتياً بشكل فوري.

### ج. جاهزية الأمان والحماية (Security Readiness - 100%)
* **عزل البيانات بالفروع (Branch Isolation)**: تطبيق مرشحات الاستعلامات العامة (Global Query Filters) في الـ DbContext لجميع الجداول العملياتية والمحاسبية لضمان عدم تسريب أي سجل ينتمي لفرع آخر.
* **أمن المستندات الحساسة**: حظر تنزيل مستندات العملاء إلا بعد التحقق من مطابقة فرع المستخدم الحالي مع فرع العميل المرتبط بالمستند.
* **الصلاحيات والأدوار**: بناء نظام تنقل (Navigation) في القائمة الجانبية يعتمد بالكامل على فلترة دور وصلاحيات المستخدم، وحظر محاولات الدخول المباشر.

### د. جاهزية التوافق المحاسبي (Accounting Readiness - 100%)
* **توازن الميزانية العمومية**: احتساب صافي أرباح الفترة ديناميكياً من الإيرادات والمصروفات، وإدماجه فوراً ضمن حقوق الملكية لضمان التطابق الحتمي: **`الأصول = الالتزامات + حقوق الملكية`**.
* **التقريب الحتمي للمبالغ**: إلزام استخدام أداة `Math.Round(..., 2, MidpointRounding.AwayFromZero)` لضمان تطابق الأرصدة والقيود المحاسبية ومنع الكسور المتناهية الصغر في SQLite والـ Ledger.
* **قاعدة القيود غير القابلة للتعديل**: حظر تعديل أي قيد يومي مرحل، وتطبيق سياسة عكس القيود (Reversal Entries) للتراجع عن المبيعات الملغاة محاسبياً.

### هـ. جاهزية الاختبارات (Testing Readiness - 100%)
* **الاختبارات التلقائية (Automated Tests)**: تنفيذ 28 اختباراً برمجياً تغطي العمليات المعقدة مثل:
  * تراجع العمليات بالكامل (Rollback) عند فشل القيود المالية في البيع والشراء.
  * جدولة الأقساط واحتساب الفوائد والضرائب محاسبياً بشكل سليم.
  * مطابقة وتوازن تقارير الميزانية وتصفية أعمار الأقساط والتحقق من عزل الفروع في الاختبارات.

## 3. البنود المطلوبة قبل الانطلاق النهائي (Pre-Go-Live Missing Items)

على الرغم من جاهزية التطبيق البرمجية والتقنية بنسبة 100%، يوصى بالقيام بالخطوات التشغيلية التالية قبل فتح النظام رسمياً للعملاء:

1. **ضبط قاعدة بيانات الإنتاج والذاكرة المؤقتة (Production Database & Cache - مكتمل ومتحقق منه)**:
   * تم ترحيل وإعداد قاعدة البيانات والذاكرة المؤقتة بالكامل على خادم PostgreSQL و Redis للإنتاج الفعلي باستخدام الحاويات (Docker)، مع تفعيل فحوصات الصحة والنسخ الاحتياطي التلقائي وسكربتات الاستعادة.
2. **تثبيت شهادات الأمان (SSL/HTTPS)**:
   * إعداد تخديم الواجهة والـ API تحت بروتوكول HTTPS الآمن لتشفير بيانات المصادقة والـ JWT tokens في الشبكة.
3. **تدوير مفتاح أمان الـ JWT (Key Rotation)**:
   * تغيير كلمة السر الافتراضية الخاصة بـ JWT في ملف `appsettings.json` لبيئة الإنتاج بمفتاح قوي ومشفر بطول 256 بت على الأقل.
4. **تهيئة الفروع والمستخدمين الأوليين**:
   * إدخال قائمة فروع المعرض الحقيقية والمستخدمين الأوليين مع تحديد أدوارهم (محاسب، بائع، مدير) بدقة لضمان بدء النظام بهوية صحيحة.
