# تقرير تكامل الواجهة الأمامية للمؤسسة والربط مع الـ API (V2 Phase 5 Frontend Report)

يوضح هذا التقرير حالة إنجاز ومخرجات المرحلة الخامسة (Phase 5) المتمثلة في ربط واجهة المستخدم التفاعلية (Next.js Frontend) بالخادم الخلفي الجديد (ASP.NET Core API) بنظام أمان JWT Bearer Token وعزل الفروع وتصفية الصلاحيات مع تفعيل المظهر المضيء الاحترافي الافتراضي والاتجاه العربي RTL بالكامل.

---

## 1. تفاصيل الربط والتكامل مع الـ API (API Integration & JWT Bearer)

تم استبدال نظام المصادقة القديم المعتمد على الجلسات المحلية (Flask Session Cookie) بنظام أمان مؤسسات متكامل مع ASP.NET Core API باستخدام **JWT Tokens**:
1. **عميل الـ API المحسن (`client.ts`)**:
   * إضافة **Request Interceptor** لقراءة الرمز المميز (JWT Token) المخزن في حالة المصادقة وإرفاقه تلقائياً كـ `Authorization: Bearer <Token>` في رأس كل طلب مرسل إلى الـ API.
   * إضافة **Response Interceptor** للكشف التلقائي عن انتهاء الجلسة (رمز الحالة `401 Unauthorized`) ومسح بيانات المصادقة محلياً وإعادة توجيه المستخدم لصفحة تسجيل الدخول.
2. **صفحة تسجيل الدخول (`login/page.tsx`)**:
   * تعديل صفحة تسجيل الدخول لاستقبال كائن الاستجابة المتكامل من ASP.NET Core والمحتوي على الـ `token` ومعلومات المستخدم (`user`) وصلاحياته وتفاصيل الفروع المتوفرة والفرع الافتراضي وتخزينها بالكامل في مخزن الحالة المحفوظ (`sessionStorage`).
3. **بروكسي الخادم (`next.config.js`)**:
   * تحديث إعدادات البروكسي لتوجيه كافة طلبات الواجهة الأمامية ذات البادئة `/api/:path*` نحو خادم ASP.NET Core (على المنفذ `8080` بدلاً من Flask على المنفذ `5000`).
   * توجيه طلبات تغيير الفروع محلياً من `/branch/switch` إلى مسار الـ API المخصص للتبديل في خادم ASP.NET Core وهو `/api/auth/switch-branch`.
   * تحديث تهيئة الصور (`images.remotePatterns`) لتدعم منفذ خادم الأصول الجديد `8080`.

---

## 2. تبديل الفروع وعزل البيانات (Secure Branch Switching)

* **آلية التبديل والتأمين**:
  * تم بناء نقطة اتصال مخصصة في خادم ASP.NET Core (`AuthController.SwitchBranch`) تستقبل طلب تبديل الفرع، وتتحقق من صحة وصلاحية الفرع المطلوب وهوية المستخدم.
  * بمجرد التحقق، يقوم الخادم بتوليد **رمز JWT جديد تماماً** يحتوي على المطالبة المحدثة `"BranchId"`.
  * يستقبل المكون `BranchSelector.tsx` الاستجابة، ويقوم بتحديث مخزن الحالة بالـ Token الجديد والمستخدم المحدث فوراً، مما يضمن أن كافة الطلبات اللاحقة للـ API ستعزل البيانات تلقائياً للفرع الجديد بناءً على الـ Token المحدث.

## 3. الصلاحيات وشريط التنقل المتجاوب (Role/Permission Aware Navigation)

* تم ربط شريط التنقل الجانبي (`Sidebar.tsx`) بنظام الصلاحيات والأدوار الفعلي للمستخدمين:
  * بناء دالة تصفية مخصصة `hasAccess` تتحقق من دور المستخدم الحالي وصلاحياته قبل إظهار أي عنصر في القائمة الجانبية.
  * إخفاء روابط الإدارة والتحكم بالنظام والنسخ الاحتياطي عن المستخدمين غير المالكين والمدراء.
  * إخفاء روابط المحاسبة وميزان المراجعة وسلامة البيانات والميزانية والتقارير المالية عن موظفي المبيعات والمهام غير المحاسبية.
  * إخفاء روابط المشتريات والأقساط عن موظفي المبيعات الأساسيين.
  * تصفية المجموعات المفتوحة افتراضياً والتحقق من التناسق لضمان عدم إظهار مجموعات فارغة.

## 4. المظهر العربي المضيء الافتراضي (RTL Arabic & Professional Light Theme)

1. **الاتجاه والخطوط (RTL Arabic)**:
   * تفعيل اتجاه RTL الافتراضي للغة العربية في المخطط الهيكلي الأساسي (`layout.jsx`).
   * إدماج خطوط ويب احترافية ممتازة تلائم تصميم لوحات التحكم للمؤسسات مثل **Cairo** للعناوين الأساسية والخط المريح للقراءة **IBM Plex Sans Arabic** للنصوص والجداول والقيم المالية.
2. **المظهر المضيء الاحترافي (Light Theme)**:
   * تحديث المكون `ThemeToggle.jsx` ليكون المظهر المضيء (`light`) هو الخيار الافتراضي للتطبيق عند أول تشغيل بدلاً من الوضع الداكن.
   * المظهر المضيء مبني بنظام ألوان HSL متناسق وجذاب للغاية يعتمد على درجات الأبيض الناصع والخلفية المريحة للعين `#F8FAFC` مع لمسات رمادية وزرقاء احترافية في الجداول والتقارير وبطاقات الأداء.
