# V2 Test Seeding Fix Report (تقرير إصلاح بذور بيانات الاختبارات v2)

يوضح هذا التقرير التفاصيل المتعلقة بمعالجة وإصلاح فشل بعض اختبارات العملاء بسبب قيود المفاتيح الأجنبية (FOREIGN KEY constraint failed) بعد التحول إلى SQLite In-Memory.

---

## 1. Root Cause (السبب الجذري للمشكلة)
في اختبارات العملاء السابقة، تم زرع بيانات العميل في قاعدة البيانات مباشرة بقيم معرفات عشوائية للحسابات والفروع:
```csharp
AccountId = Guid.NewGuid(),
BranchId = _testBranchId
```
بما أن جداول الحسابات (`Accounts`) والفروع (`Branches`) لم تكن تحتوي على سجلات بهذه المعرفات العشوائية؛ فإن محاولة حفظ سجل العميل أدت إلى إلقاء استثناء بخرق قيد المفتاح الأجنبي (Foreign Key Violation) لأن حقل `Customer.AccountId` يعتمد ويعبر عن علاقة ربط وثيقة بحقل `Account.Id`.

---

## 2. لماذا كشفت أداة SQLite المشكلة؟ (Why SQLite Exposed the Issue)
* **قاعدة البيانات الافتراضية السابقة (EF Core InMemory)**: لا تقوم بالتحقق من قيود العلاقات (Relational Constraints) أو المفاتيح الأجنبية (Foreign Keys) وتتعامل مع الجداول كسجلات كائنات بسيطة في الذاكرة. لذلك كانت تقبل المعرفات العشوائية الوهمية دون اعتراض.
* **قاعدة البيانات الحالية (SQLite In-Memory)**: محرك علائقي حقيقي (SQL Database Engine) يفرض تكامل وتطابق البيانات وقيود المفاتيح الأجنبية بدقة تامة. لذلك كشف فوراً وجود معرفات غير مسجلة في الجداول المقابلة ومنع إدخالها لحماية سلامة البيانات.
