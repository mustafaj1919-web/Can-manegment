# خطة تنفيذ مشروع إدارة معرض السيارات v2.0 Enterprise

يوضح هذا المستند خطة العمل التفصيلية المكونة من 4 مراحل للانتقال بنظام إدارة معرض السيارات من الإصدار v1 الحالي المبني على بايثون إلى الإصدار الجديد بالكامل v2.0 Enterprise Edition المبني على تقنيات .NET و Kubernetes و PostgreSQL.

---

## المرحلة الأولى: تأسيس البنية التحتية والأمان (التجهيز الهيكلي)
* **المدة**: 4 أسابيع.
* **الأهداف الرئيسية**:
  * بناء الـ Solution والمشاريع التابعة لـ Clean Architecture.
  * إعداد قاعدة البيانات وتفعيل معترِض الحفظ لحماية القيود والبيانات المالية.
  * تشغيل خدمة الهوية والمصادقة وتوليد رموز JWT متكاملة مع Claim لعزل الفروع.
  * أتمتة البناء والاختبار عبر سير عمل GitHub Actions.
* **المخرجات البرمجية**:
  * ملف `CarShowroomManagementV2.sln` والمشاريع الخمسة.
  * الكيانات الأساسية في الـ Domain والـ DbContext والـ Interceptor.
  * ملفات تكوين Docker Compose و Kubernetes Manifests للـ API وقاعدة البيانات و Redis.
  * المستندات الهندسية الأساسية.

## المرحلة الثانية: الخدمات الأساسية والواجهات (تأسيس المحرك)
* **المدة**: 6 أسابيع.
* **الأهداف الرئيسية**:
  * بناء وتطوير الخدمات الأساسية للمبيعات والمخزون.
  * تصميم واجهات Next.js المتوافقة مع هيكلية المؤسسات.
  * حماية وتأمين المستندات المرفوعة للعملاء في مسار معزول (Secure Private Storage).
* **المخرجات البرمجية**:
  * واجهات API كاملة للمخزون والسيارات وتكاليف الصيانة والجمارك.
  * واجهات API لإدارة العملاء ورفع الهويات الشخصية.
  * بناء شاشات لوحة التحكم للواجهة الأمامية والربط بـ API الجديد.

## المرحلة الثالثة: العمليات المالية والتشغيل المتوازي (الاختبار الواقعي)
* **المدة**: 4 أسابيع.
* **الأهداف الرئيسية**:
  * إكمال النواة المحاسبية والقيود اليومية التلقائية.
  * تفعيل مزامنة وتكرار البيانات بين النظامين v1 و v2 عبر CDC أو Logical Replication.
  * تشغيل النظامين جنباً إلى جنب لمقارنة النتائج والتقارير المالية.
* **المخرجات البرمجية**:
  * واجهة برمجة القيود والتقارير المالية (ميزان المراجعة، الأرباح والخسائر، الميزانية العمومية).
  * خوادم مزامنة البيانات (Debezium/Kafka).
  * سجلات تدقيق تفصيلية (Audit Trail) للمقارنة المالية للتأكد من خلو النظام من الأخطاء المالية قبل التحول الكامل.

## المرحلة الرابعة: النقل الكامل والاستقرار (الانطلاق النهائي)
* **المدة**: أسبوعان.
* **الأهداف الرئيسية**:
  * التحول النهائي وتوجيه حركة المرور بنسبة 100% لنظام v2 Enterprise.
  * تفعيل خدمة النسخ الاحتياطي التلقائي المجدولة واستعادتها.
  * إغلاق وأرشفة نظام v1 نهائياً.
* **المخرجات البرمجية**:
  * تكوينات Kubernetes Ingress المحدثة لتوجيه حركة المرور بالكامل إلى النظام الجديد.
  * CronJobs مخصصة للنسخ الاحتياطي السحابي المشفر.
  * تقرير إتمام المشروع وخطة الدعم الفني.
